Capabilities

Portable by design. Defensive by default.

The same auditable Python code runs on Linux, Termux, macOS, Windows Terminal, and PowerShell without installing a single runtime package.

01

Zero dependencies

Built only with the Python standard library and shipped as one runnable, readable file you can review end to end.

02

Cross-platform

Explicit handling for IPv4, IPv6, POSIX and Windows socket codes, terminal capabilities, and portable installers.

03

Safe limits

Bounded CIDR expansion, an authorization gate, per-socket timeouts, throttling, and graceful Ctrl+C interruption.

04

Useful output

Readable tables plus stable JSON and CSV for defensive automation, evidence collection, and diffing over time.

05

Banner protection

Service banners are capped at 256 bytes and stripped of ANSI and control sequences before they reach your terminal.

06

No stealth features

TCP connect scanning only — no spoofing, raw packets, evasion, or exploitation behaviour, intentionally and permanently.

Live output

Three formats. One scan.

Result data goes to stdout; branding, warnings, and progress go to stderr, so piping stays clean.

The responsible-use warning is always printed to stderr, including in --quiet mode.

Installation

One command. Verified before it runs.

The installers are idempotent, check for Python, verify the downloaded scanner against SHA256SUMS, and install the command name klahack-portscope.

Linux shell

Run it in a terminal. The installer uses /usr/local/bin where available, or ~/.local/bin when sudo is unavailable.

curl -fsSL https://raw.githubusercontent.com/klahack/klahack-portscope/main/install.sh | bash

Termux on Android

Termux is detected automatically and the command is installed under $PREFIX/bin. No root is required.

curl -fsSL https://raw.githubusercontent.com/klahack/klahack-portscope/main/install.sh | bash

macOS Terminal

Same POSIX installer. If sudo is unavailable it falls back to ~/.local/bin, so add that directory to your PATH.

curl -fsSL https://raw.githubusercontent.com/klahack/klahack-portscope/main/install.sh | bash

Windows PowerShell

Per-user installation under %LOCALAPPDATA%\klahack-portscope. No Administrator privileges are needed; open a new terminal afterwards.

irm https://raw.githubusercontent.com/klahack/klahack-portscope/main/install.ps1 | iex

Verify before execution

Download → inspect → verify → run

Piping is convenient, but a security tool deserves a deliberate installation path. This is the safest workflow.

  1. 01

    Download

    Fetch install.sh or install.ps1 together with SHA256SUMS directly from the repository.

  2. 02

    Inspect

    Read the whole installer and understand every command it will execute on your machine.

  3. 03

    Verify

    Download klahack_portscope.py and compare its SHA256 digest against SHA256SUMS before trusting it.

  4. 04

    Run

    Execute the inspected installer only after the source and the checksum both meet your expectations.

Run straight from source

No installation required — the single file is executable as-is.

python3 klahack_portscope.py --version

Verify a checksum manually

Compare the digest yourself before running anything.

sha256sum -c SHA256SUMS

Usage

Start narrow. Widen only with permission.

Every invocation prints a compact brand banner to stderr unless --quiet is supplied. These examples use loopback or private addresses only.

klahack-portscope -t TARGET (-p PORTS | --top-ports N) [options]

01Scan selected loopback ports, including a small range

klahack-portscope -t 127.0.0.1 -p 22,80,443,8000-8010

02Scan the 20 most prevalent ports on localhost and emit JSON

klahack-portscope -t localhost --top-ports 20 --json

03Throttle an authorized private-network scan and save CSV

klahack-portscope -t 192.168.1.0/24 -p 22,80,443 --delay 0.05 --csv --output audit.csv

04Assert authorization for a public target in non-interactive use

klahack-portscope -t 203.0.113.10 -p 443 --i-have-permission

The flag is an authorization confirmation, not a substitute for actual written permission.

How it works

A normal connect scan. Nothing hidden.

The scanner performs a full TCP connect scan through the operating system's normal socket API. It never crafts raw packets.

open

The TCP connection succeeded, so a service accepted the handshake on that port.

closed

The connection was refused (ECONNREFUSED, or Windows WSAECONNREFUSED 10061), so the host responded.

filtered

The attempt timed out, had no route, or failed in a way that cannot prove the port is closed.

Bounded execution engine

  • Work is submitted to a ThreadPoolExecutor in bounded batches instead of materializing every host and port pair.
  • Every socket is context-managed, so descriptors are released deterministically.
  • Ctrl+C stops new work, waits for the small in-flight batch, emits completed partial results, and returns exit code 130.
  • Banners are read passively first; a basic HEAD request is only sent on common HTTP ports when nothing arrives.

Authorization safeguard

  • Resolved addresses are classified with Python's ipaddress module before any socket is opened.
  • Private, loopback, and link-local targets proceed without an extra prompt.
  • Any other address requires an interactive yes, or --i-have-permission in non-interactive runs.
  • Otherwise the command refuses to scan and returns exit code 2; --max-hosts also caps oversized ranges.

Honest limitations

  • TCP only; there is no UDP scanner.
  • Connect scans complete the operating system TCP handshake; there is no SYN or raw-packet scan.
  • Service names are port-based hints and banners are untrusted hints, not definitive identification.
  • Firewalls can make closed or unreachable ports appear filtered.
  • DNS answers and local service databases can differ by operating system.
  • This focused audit utility is not a replacement for nmap or a complete vulnerability assessment.

Development and tests

  • The test suite uses unittest and binds only to 127.0.0.1; it never scans an external network.
  • CI runs Python 3.8 and 3.12 on Ubuntu, macOS, and Windows.
  • Tagged releases also build standalone PyInstaller executables; PyInstaller is a build-time dependency only.
python -m unittest discover -s tests
